Systems & Details

Details A–C · concurrency-tested architectures

A3

PgQueue

2024 · Durable Job Queue on PostgreSQL github.com/nitish9302/pgqueue
Engineering Notes
  1. Zero Duplicate Claims: Concurrent workers poll and claim jobs with FOR UPDATE SKIP LOCKED, eliminating lock contention and ensuring no job is ever claimed twice simultaneously.
  2. Lease-Based Crash Recovery: Active workers maintain periodic heartbeats. A background Expiry Reaper daemon identifies abandoned jobs from crashed workers (expires_at < NOW()) and safely recycles them back into the active queue.
  3. Fenced Completion & Chaos Tested: Updates use monotonic token fencing so a resurrected, lagging worker can never overwrite state. Hardened and verified using chaos tests that terminate worker processes mid-execution.
  4. Transactional Enqueue & DLQ: Allows callers to commit queue jobs inside their own local database transactions atomically. Built-in exponential backoff with full jitter and dead-letter queue routing for poison pills.
B3

HookRelay

2024 · Multi-Tenant Webhook Delivery Platform github.com/nitish9302/hookrelay
Engineering Notes
  1. Transactional Outbox Architecture: Eliminates the dual-write problem by writing the event, initial delivery record, and PgQueue dispatch job within one atomic PostgreSQL transaction. If the service crashes, no accepted event is lost.
  2. SSRF & Network Hardening: Ingestion requests resolve target IPs against blocked private CIDR blocks (RFC 1918/3927) and validate against DNS rebinding attacks before dispatching HTTP payloads.
  3. Circuit Breakers & Jittered Retries: Per-endpoint circuit breakers automatically trip when a subscriber experiences downtime, preventing thread starvation. Complies with Retry-After headers.
  4. Cryptographic Verification & Isolation: Every payload is signed with an HMAC-SHA256 header using per-subscriber secret keys. Tenant-isolated queues prevent one slow subscriber from degrading delivery for other tenants.
C3

SeatLock

2024 · High-Contention Seat Reservation System github.com/nitish9302/seatlock
Engineering Notes
  1. Deadlock Eradication via Ordered Locking: Implemented and stress-tested 4 concurrency models with k6. Sorting seat IDs before acquiring row-level locks mathematically eliminates cyclic wait graphs, sustaining zero deadlocks even under peak bursts.
  2. Atomic All-or-Nothing Holds: Ensures grouped seats are reserved together or not at all. Abandoned reservations expire via a 5-minute TTL without blocking other concurrent buyers.
  3. 3-Phase Payment Confirmation: Idempotent payment reference tokens ensure that payment gateway webhook retries or connection drops cannot lead to double billing or stuck pending locks.
  4. Real-Time SSE Streaming via LISTEN/NOTIFY: State transitions trigger PostgreSQL NOTIFY seat_events, which Node.js fans out over Server-Sent Events (SSE) so all connected clients see instant seat availability without HTTP polling overhead.
