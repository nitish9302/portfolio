Production Systems

Details A–C · systems built, load-tested & hardened against failure

A3

PgQueue

Durable Job Queue on PostgreSQL · Node.js, TypeScript, PostgreSQL, Docker github.com/nitish9302/pgqueue
Project Engineering Bullets (From Resume)
  1. Zero Duplicate Pickups: Built a durable job queue library and admin API on PostgreSQL where concurrent workers claim jobs with FOR UPDATE SKIP LOCKED, so no job is ever picked up twice even with many workers running in parallel.
  2. Lease-Based Crash Recovery: Achieved at-least-once delivery with lease-based crash recovery (worker heartbeats, an expiry reaper that reassigns jobs from crashed workers, fenced completion updates), verified with chaos tests that kill workers mid-processing.
  3. Exponential Backoff & Idempotency: Added exponential backoff with full jitter, dead-letter handling for repeatedly failing jobs, idempotency keys, and transactional enqueue so jobs commit atomically with the caller's own database changes.
  4. EXPLAIN ANALYZE Tuning: Profiled the job-claim query with EXPLAIN ANALYZE and tuned indexes so claiming stays fast as the jobs table grows.
B3

HookRelay

Multi-Tenant Webhook Delivery Platform · Node.js, TypeScript, PostgreSQL, Docker github.com/nitish9302/hookrelay
Project Engineering Bullets (From Resume)
  1. Fan-Out Built on PgQueue: Built a multi-tenant webhook delivery platform on top of PgQueue that fans events out to subscriber endpoints with HMAC-SHA256-signed payloads and automatic retries.
  2. Zero Lost Events via Outbox: Guaranteed no accepted event is lost using a transactional outbox (the event, its delivery records, and its queue jobs commit in one PostgreSQL transaction), validated with crash-injection tests.
  3. Circuit Breaker & Replay: Added a per-endpoint circuit breaker, a jittered retry schedule that respects Retry-After headers, and replay of failed deliveries, so a subscriber's temporary outage never becomes permanent data loss.
  4. SSRF Hardening & Isolation: Hardened ingestion against SSRF (private-IP blocking, DNS-rebinding protection) and secured it with hashed API keys, per-tenant rate limiting, and idempotent ingestion, isolating slow endpoints so one bad tenant cannot delay everyone else's deliveries.
C3

SeatLock

High-Contention Seat Reservation System · Node.js, TypeScript, PostgreSQL, Docker github.com/nitish9302/seatlock
Project Engineering Bullets (From Resume)
  1. Atomic Holds & Anti-Overselling: Built a reservation backend with atomic all-or-nothing seat holds, automatic expiry of abandoned holds, and idempotent booking APIs, preventing overselling when many users grab the same seats at once.
  2. k6 Concurrency Evaluation: Implemented and load-tested four concurrency strategies with k6 (atomic updates, ordered row locks, optimistic versioning, naive baseline) and used the results to pick ordered locking, which eliminated deadlocks under heavy contention.
  3. 3-Phase Payment & Reconciliation: Designed a three-phase payment confirmation with idempotent payment references and a reconciliation job that repairs expired and stuck holds, verified with crash tests and automated database invariant checks.
  4. Real-Time SSE via LISTEN/NOTIFY: Streamed live seat availability to clients over Server-Sent Events backed by PostgreSQL LISTEN/NOTIFY, so every browser shows the same seat state without polling.
